# Demonstration dataset

`grant_applications.csv` contains 60 **simulated** grant applications generated by `generate_synthetic_data.py` with fixed seed `20261102`. It does not contain real applications, observed programme outcomes, or information from an external data portal.

## Fields and units

| Field | Meaning |
|---|---|
| `application_id` | Unique simulated application identifier |
| `project_name`, `region`, `sector` | Descriptive simulated labels |
| `requested_amount` | Requested funding in Indian rupees (INR) |
| five `*_score` fields | Analyst-designed, simulated impact estimates from 1 to 10 |

## Scoring rubric

For every criterion, 1 represents very limited expected contribution relative to the other proposals, while 10 represents an exceptional expected contribution supported by a strong proposal case. Intermediate values reflect the following criterion-specific judgment:

| Criterion | Score 1 | Score 10 |
|---|---|---|
| Poverty reduction | Little expected improvement for low-income households | Strong, credible improvement for highly deprived households |
| Employment generation | Few, temporary, or weak employment opportunities | Large, durable, inclusive employment opportunities |
| Healthcare impact | Minimal expected improvement in access or health outcomes | Major expected improvement in health access or outcomes |
| Education impact | Minimal expected improvement in learning or access | Major expected improvement in learning, retention, or access |
| Beneficiaries | Very few direct beneficiaries | Very large, well-defined beneficiary reach |

## Replacing the data

Replace the CSV with a file containing the same columns, units, and 1--10 score scale. The loader validates missing values, duplicate IDs, non-numeric values, non-positive requested amounts, and out-of-range scores before any ranking runs. When real source data lack impact scores, label any added scores as analyst estimates rather than observed outcomes.
